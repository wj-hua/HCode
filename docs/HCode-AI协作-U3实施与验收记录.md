## 完成行为

当前输入选择“协作执行”，在侧面板选“隔离代码交付”。当前 Claude/Codex 原会话只读实际项目资料，生成一或两项代码任务草案。用户调整并保存范围，核对完整复制清单、检查命令和独立审查配置，明确确认后才创建隔离副本。

- 任务包含名称、实现与验收目标、分工依据、执行 AI、模型和准确允许文件，包含需要新增的测试。信息不足时保留空任务，说明需要补充的资料，允许用户明确填写；不伪造已实现或已验证结果。
- 只开放既有 macOS 普通 Node Git 项目准入；模型不能提交任意 shell、安装依赖或扩展到移动端/Java 构建。宿主从实际项目发现有限检查 ID 和对应命令。Gemini 不开放写入，只能在账号模型明确选择后承担已准入的只读审查。
- 单任务和双任务都冻结准确文件范围。两项任务不接受声明的依赖、重复/大小写重叠或祖先路径重叠；目录、链接、范围外路径和通配符拒绝。需要共享修改文件或顺序依赖时须合成完整单任务。
- 复制清单包含当前未提交、未跟踪及 ignored 文件/依赖，不含 `.git`。显示实际文件数量、容量和全部文件路径；按页展示，不裁剪确认范围。内容、权限等版本由既有清单哈希绑定。
- 修改目标、分工、路径、模型、审查者或检查项立即撤销旧确认。必须先保存，再接受范围与检查；不能在修改时同时提交接受。检查缺失、预算不足、路径问题与未保存原因在开始附近显示。
- 确认时重新检查复制清单、Git 状态/基线、检查命令、资料哈希、后端版本/能力与原会话配置。变化明确拒绝；生成、编辑和放弃均不建立候选副本。
- 固定草案 ID 创建唯一 Run；同版本并发确认及重复确认返回同一记录。确认后由宿主派发冻结任务，不再让原 AI 二次拆分或扩大权限。
- 每项独立复制共同基线、实现、冻结版本、运行必需检查、独立审查；有阻塞意见才按现有上限修订和复审。最终仍由原会话汇总。单任务最低 4 回合，双任务最低 6；规划/格式纠正/修订共同使用 12 回合。
- 通过验证和审查仍显示待采纳；用户选择最新冻结版本、查看差异、检查冲突、单独接受后逐项应用。旧版本、源文件后续变化、未完成采纳/锁定、缺同版本检查或审查证据继续拒绝。采纳和恢复不暴露给模型，不自动合并、提交或推送。
- 第一项已采纳不等于第二项已采纳；冲突说明限定为本次候选未写入。两份独立候选的组合效果仍需在原项目复测，历史主持汇总标记为采纳前结果。

## 改动边界与 Apple Design

| 边界 | 职责 |
| --- | --- |
| `shared/codeDraft.ts`、`codePlanRules.ts` | 草案契约、准确路径/依赖/重叠/能力/预算等纯规则；主进程和界面共用，不把判断复制两份 |
| `drafts/CodeDraftService/Policy/Contracts` | 原会话规划、宿主项目准入、版本确认；复用共同 DraftLifecycle、Repository、DraftPlanner |
| `CollaborationService/Runner` | 接收已确认单/双任务，保留规划回合并固定派发；复用原 Workspace、Validation、Review、Adoption 引擎 |
| `CodeDraftPanel/Tasks/Scope/Review/useCodeDraft` | 计划预览、编辑与明确开始；候选、差异、冲突和逐项采纳继续由原结果组件负责 |
| `useDraftState` | 专家/代码草案共用订阅、版本排序和操作反馈；各模式保留自己的业务动作 |
| 类型化 IPC | 七个代码草案命令及一个更新事件，沿用 preload 白名单和规划取消路由 |

旧单任务顶层 `code` 与双任务记录保持可读；新计划通过一或两项准确范围的任务列表交付。删除已无消费者的 `CodeValidationPlan/ParallelCodeSetup`，新流程不再保留立即执行的旧 UI。旧直接启动 API 保持兼容，没有新增依赖、平台准入、联网/设备能力或自由消息协议。

交互使用既有字体、Token、按钮和侧面板。任务分工、准确路径和必需检查优先展示；模型、完整复制清单、未提交上下文及原生记录按需展开。生成与执行是两个明确动作，加载、取消、未保存、冲突与成功都提供文字反馈；主操作有按压/键盘焦点，加载尊重减少动态效果。关闭侧面板只关闭展示，返回保留任务和编辑。完整 VoiceOver、系统缩放和多尺寸验收仍留在 U6。
