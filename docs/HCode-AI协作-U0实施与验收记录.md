## 1. 完成范围

U0 已打通一项只读任务的完整路径：当前 Claude/Codex 原会话生成结构化草案 → 用户编辑并确认版本 → 宿主派发唯一任务 → 执行与独立审查 → 原会话汇总。

- 草案使用独立契约与 Repository，创建、编辑、放弃不调用模型、不创建 Run 或代码副本。
- 规划使用已验收的受限 ResearchRuntime；Claude 仅开放宿主工具，Codex 使用项目只读、无网络权限。稳定协作工具目录仍可恢复，但草案阶段的所有执行工具处理器明确拒绝调用。
- `taskObjective` 只表达执行者交付内容，`summary` 表达分工及计划说明；执行目标不包含模型生成的“尚未安排任务”等规划状态。
- 用户确认时核对草案版本、实际工具读取的文件内容 hash、源会话及后端资格、模型和累计预算。相同版本重复确认只对应一个固定 Run ID。
- 先保存启动意图，再创建 Run；响应丢失后可显式找回同一结果，旧版本和保存失败不能绕过准入。已落盘的 Run 重启后只读取，不再次派发。
- 规划尝试、取消及失败都计入累计回合；启动后复用已有规划结果，不另跑主持拆解回合。
- 取消等待可信回合终态，再显示取消。SDK 原生失败/取消 outcome 保留；用户看到简短取消说明，原始诊断放在详情。原生停止未知仍保持阻塞。
- 草案可按本地 key 或原生会话 ID 找回，历史视图重开不创建替代线程；源码变化、缺工具历史线程和预算不足均明确阻止错误开始。

## 2. 界面与 Apple Design

在原“多 AI 协作”的只读入口增加最小计划预览，本轮没有提前实现 U1 的统一工作方式或侧面板迁移。

- 生成、编辑保存、确认开始、取消和放弃有分开的动作；未保存修改会禁用确认，并说明下一步。
- 立即显示规划中和取消等待反馈；取消不是红色 SDK 诊断，显示“规划已取消，未启动协作”。
- 标明资料边界、执行 AI、独立审查 AI、原会话汇总和累计预算；文件 hash 与原生诊断按需展开。
- 控件保留项目组件与 Token，补键盘焦点反馈、按压反馈和关闭后回到入口的焦点恢复；加载动画尊重减少动态效果。
- 明示本轮只使用计划入口的文字和项目文件，普通聊天输入框附件不带入；不会把尚未实现的附件传递展示为支持。

键盘从目标字段进入执行者选择已实测；计划修改、禁用确认、保存、新版本、关闭/重开、历史重开、取消及真实运行已实测。完整 VoiceOver、系统缩放及减少动态效果设置下的体验留在 U6，不宣称全部无障碍验收完成。

## 5. 发现与修复

1. 首次 Codex 规划把“安排任务”和“尚未启动”放进 objective，审查者要求执行者证明已安排任务，2 次自动修订后仍未通过。原 Run `63904882-269c-48eb-8075-8626f3955644` 保留 awaitingUser；没有放宽审查或改成通过。拆开 `taskObjective/summary` 后双向真实闭环通过。
2. 模型发送前的持久化通知失败留下 running 回合。回归先复现，再使失败回合进入 interrupted，并保留错误和预算，重试可继续。
3. Claude 取消可能返回原生 failed 和诊断文字。产品层在可信终态后记录草案 cancelled，保留原生 failed；停止未确认不做此转换。
4. 历史视图初始没有本地 sessionKey 时未读取草案。补原生身份查询，读取不生成新计划；恢复的草案可继续编辑和明确开始。
