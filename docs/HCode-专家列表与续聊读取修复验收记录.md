## 读取故障及修复边界

原 Codex 会话 `01a134f7-2f34-70e1-a3c3-901ee9e93ecb` 在专家流程结束后继续普通对话，四次 `hcode_read_file` 均立即失败。原生记录只有通用 `dynamic tool request failed`。实际文件存在且小于读取上限，问题不在项目文件本身。

根因：原生线程保留创建时的动态工具目录，但评审结束撤销 ResearchRuntime 后，Session 不再处理 `item/tool/call`。因此原工具入口仍可被模型调用，却无法得到宿主读取响应；重启恢复同一线程也受影响。

修复只涉及 Codex Session 的动态工具绑定和请求分发：普通回合绑定项目读取 Runtime；协作回合仍绑定原有 ResearchRuntime。权限、审批和原生沙箱参数不变。普通回合不继承旧委派闭包和上下文动作，继续拒绝项目外读取、跨线程、旧回合与无权限工具。提前到达的 `turn/started` 也可正确绑定，避免请求和响应时序造成同类失败。

UI 状态归属 `useExpertReport`，数据来自已校验的冻结产物 IPC；团队目录和单份预览分为独立组件。未修改专家调度、报告协议、业务项目、历史备份及原评审内容。
