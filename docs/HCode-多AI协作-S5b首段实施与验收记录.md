## 用户路径与边界

在当前会话打开“多 AI 协作”，选择代码交付的冻结候选，核对完整修改前后内容、文件 hash、权限和真实检查。点击“检查所选版本能否采纳”，主进程检查版本资格及全部 touched paths；只有没有冲突时才出现版本、原项目路径和确认勾选。勾选后“确认采纳所选版本”写回整份候选。预览不写原项目，模型没有采纳工具，不能代替用户确认。

默认且本段唯一准入：最新版本、工作区未接管/丢弃、原生停止已确认、交付 accepted、匹配报告版本的独立 approved 且无阻塞项、同一代码 hash 的全部必需检查通过且退出码为 0、可写候选仍匹配冻结清单。旧版本、失败检查、审查缺失、冻结内容/权限污染、手动修改和未知停止明确阻止应用。不开放未通过候选的例外采纳。

采纳内容来自完整性校验后的冻结文件，不能从可写副本复制未经审查的内容。基线和候选清单重新推导差异，防止只更改差异数组逃避范围核对。全部原文件按内容、权限和存在状态与基线比较：新增位置被占用、待删除文件变化或目标祖先为链接均拒绝。范围外的后续人工文件改动保留。

本段支持普通文件新增、修改、删除、二进制字节和文件权限；新增父目录仅受控创建。拒绝 `.git`、`node_modules`、路径逃逸、修改符号链接、路径大小写歧义及文件/目录相互转换。沿用 S5a 的 macOS Node 项目准入，不扩展移动平台或任意项目权限。

## 模块与持久化

| 模块 | 职责 |
| --- | --- |
| `shared/codeAdoption.ts` / `adoptionContracts` | 用户采纳请求、预览、冲突、状态及严格日志契约 |
| `candidateChanges` / `adoptionArtifacts` | 从清单推导变更、核对冻结字节/权限，提供精确版本 |
| `adoptionPaths` | 根目录身份、普通文件读取、祖先链接拒绝和状态比较 |
| `adoptionJournal` | 恢复内容与校验日志持久化，文件及目录 fsync |
| `adoptionTransaction` | 原项目互斥、逐文件原件核对、排他安装、显式撤回和清理 |
| `CodeAdoptionService` | 采纳资格、预览 token、幂等、读取重启状态和恢复编排 |
| 协作 Service / IPC / Renderer | 用户入口、快照展示和禁用已应用/需恢复候选的接管与续跑 |

原项目使用 `.hcode-apply-lock` 排他目录；不同 HCode 实例/Run 不能同时应用该项目。恢复内容和校验日志位于 Run 的 `adoptions/<id>/`，原件在同一原项目文件系统的受保护临时目录中保存。日志准备和冻结备份先于替换；原件先移出并核对，候选通过排他 hard-link 安装，新出现的文件不会被覆盖。实际字节和权限在提交前再次核对。

文件系统不是跨文件原子事务：应用过程中可能暂时缺少或只更新部分文件，因此用户应暂停其他编辑器写入。准备后先重新检查全部文件，每次替换前也核对；目录被并发恶意重命名/替换的压力场景未验收，不宣称具备跨进程文件系统快照隔离。CLI/验证进程未获得原项目写入权限。

进程中断不自动继续写回。`prepared`、`applying`、`needsRecovery` 在重启后显示需要恢复。用户显式恢复时，仅撤回属于本次应用的内容；未知内容或后续人工修改阻止恢复并保留日志/原件。不会用旧基线强行覆盖新编辑。

`applied` 先于临时清理持久化；清理失败仍显示“已应用，临时文件需清理”，显式恢复只清理、不撤销成功结果。只删除自身已知临时文件和仍为空且设备/inode 身份匹配的自建目录；目录身份未记录或被替换则停止恢复，不凭路径删除；未知额外文件不删除。冻结版本、审查、检查与恢复备份均保留。日志是重启后读取应用状态的依据，即使协作快照尚未同步，也不误报原项目未改动。终结快照读取会等待源会话恢复收尾，避免提前读取完成状态后仍有异步持久化或恢复操作。

## 自动验证

- 预览不写入，版本/token 显式选择；重复应用幂等，重启显示已应用，不触发模型。

- 新增目录、二进制、删除及 755 权限采纳。
- 应用过程中再次变更文件保留修改；目标祖先链接与冻结文件污染拒绝；同名新建目录被替换时，恢复保留后续目录与人工移出的文件。

- 独立真实子进程在替换后 SIGKILL：重启发现 `applying` 日志，没有自动写入；恢复后原件正确。
- 同原项目另一采纳被锁阻止，活动候选不能接管；成功状态先持久化，未知临时文件只阻止清理。
