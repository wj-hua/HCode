## 完成行为

从当前输入选择“专家评审”并查看计划，当前 Claude/Codex 原会话读取实际项目资料后推荐团队。生成只创建独立草案，不创建专家研究运行、工作会话或冻结指令产物。用户保存分工、核对本次能力限制并明确开始后，才依次进行专家独立研究、相关角色互审、原会话汇总。

- 推荐只接受七类业务角色：iOS、安卓、前端、Java 服务端、需求调研、UI 设计、测试。每位提供本次研究任务和推荐依据；未知平台或目标不足时保留空团队，说明缺口，由用户选择，不能默认填前端/Java/测试。
- 保留 S3b 的本机固定组合：iOS/安卓结合移动端角色；Java 结合 Java、Spring Boot 和架构师；iOS/安卓/前端/设计结合 Apple Design。团队预览与启动冻结继续使用原 ExpertProfile 服务；本机角色和 Skills 文件未修改。
- 用户可选择 2–7 位专家，编辑整体目标、各自任务、执行 AI、模型与累计预算。推荐模型只决定角色与任务；宿主按用户已有 Claude/Codex 默认配置和已验证能力分配 AI。agy 不自动选入；手动选择 Gemini 时必须指定账号可用模型。
- 添加角色明确标为用户添加；修改目标、团队、任务、AI、模型或预算撤销旧能力确认。必须先保存，再单独接受限制，不接受“修改分工并同时确认”的请求。
- 仅分析项目文件，不联网、不运行测试或设备验证；Role/Skill 的方法不增加工具权限。模型重复、组合问题、模型缺失、预算不足及未确认限制都有明确说明。
- 确认时重新核对原会话配置、规划读取的文件哈希、本机组合版本、后端版本/模型能力和累计预算。发现变化明确拒绝，不自动代选模型或扩展范围。
- 一个规划、每位一个独立研究和一个互审、一个汇总，基础需求为 `2N+2`；七人最低 16 回合。格式修正及重新规划同样消耗累计预算。
- 同版本并发确认只有一个 Run；启动意图先持久化，固定 Run ID 与草案 ID 相同。回执丢失后可找回匹配确认凭据的已启动结果，文件或能力随后变化也不能触发重跑。启动后草案不能编辑；重启仅展示记录。
- 各自研究任务进入实际专家提示及对应互审提示；首轮专家报告互不可见。汇总保留真实 `expertId/versionId/claimId`，不能把多数赞同或原文互审支持称为实际测试通过。

## 改动边界

| 层 | 模块与职责 |
| --- | --- |
| 共享契约 | `planningDraft.ts` 提供共同草案生命周期，`expertDraft.ts` 定义推荐、分工、能力版本；原只读草案落盘结构和历史 Run 兼容 |
| 主进程草案 | `DraftLifecycleService` 管版本、持久化、预算预留、取消与幂等；Research/Expert Policy 各自管业务规则；`DraftPlanner.propose` 共用受限原会话规划 |
| 专家调度 | `CollaborationService.startPreparedExperts` 接收已确认分工和规划回合；原 ExpertWorkflow 继续独立研究、冻结报告、互审与汇总 |
| 界面 | `ExpertDraftPanel/ExpertDraftTeam/useExpertDraft` 管预览、未保存编辑和操作反馈；结果优先汇总，详细报告与原生回合按需展开 |
| IPC | 专家草案七个类型化命令和一个更新事件，沿用 preload 白名单及现有会话工具桥接 |

删除已无消费者的旧手动 `ExpertSetup/useExpertProfiles`，保留承担兼容接口的 ResearchDraftService 和旧直接启动专家 API。没有新增依赖、网络/设备工具或修改权限策略；未改普通聊天、同题对比、代码验证/采纳与正式安装包。

Apple Design 落地使用现有字体、Token、按钮和侧面板：角色/任务/执行 AI 优先，模型、Skills、预算按需展开；加载、未保存、错误和能力缺口提供文字反馈；按压与键盘焦点可见，推荐加载动画尊重减少动态效果。结果展示共识、分歧与验证缺口，长来源入口换行避免溢出。完整 VoiceOver、系统缩放和多尺寸验收留在 U6。
