## S2 已交付的用户行为

| 垂直行为 | 可观察结果 | 边界 |
| --- | --- | --- |
| 执行者提出澄清 | 受限 `request_context` 绑定当前 Run/Delivery；幂等问题立即落盘；`wait_tasks` 返回 needsInput，父 AI 可读取问题 | 不等待用户占据工作者槽；不生成猜测产物送审 |
| AI 或用户回复 | 发起 AI 只可回复已有上下文；`requiresUser` 问题必须用户回答；用户在界面保存回复 | replyTo 绑定原问题；重复同一回复幂等，不覆盖已有答案；拒绝跨 Run ID |
| 回复后继续 | 父 AI 在本回合提供上下文时，由宿主在执行者回合结束后续跑；用户回复后选择恢复具体任务 | 报告与审查读取同一份消息；延续原生执行会话；权限集合不变 |
| 暂停并接管 | 先落盘 stopping，阻止新派发并中断活动回合；可信停止后 paused | 未获原生确认显示 interrupted 与原因，并保留执行锁；不假暂停 |
| 整体停止或任务级停止 | 整体停止释放工具等待、终结排队任务并中断活动任务；任务级停止保留父会话失败汇总 | 排队任务不启动 CLI；迟到成功不唤醒父 AI；不杀共享 app-server |
| 人工补上下文、重做、重新审查 | 针对指定交付继续，保留原版本和所有意见；重新审查可针对同一冻结版本 | 原报告/证据变化使旧接受结果失效，需重新调研；不手工伪造 approved |
| 重启查看与显式续跑 | 展示持久化报告/审查；未知执行状态为 interrupted；等待用户动作 | 不自动重跑、不回补未知副作用；原发起会话的原生身份保留 |
| 尾行修复 | 坏 Run 单列，不遮蔽健康记录；用户可备份完整日志并截去未提交的半截尾行 | 前缀须校验完整连续；中间损坏、跳号、完整 JSON 缺提交分隔不自动修改 |
| 累计预算与用量 | 回合上限 12、工作者并发 2、消息上限 40；人工重试不重置预算；显示已知 Token 与未知回合数 | 每次派发预留审查/汇总；额度错误明确返回，不自动换模型或扩权限 |

普通会话与协作的占用同时绑定界面 key 和原生会话身份。重开窗口生成新 key 不能绕过锁；从界面恢复旧协作时绑定原协作 key，使流式回传显示在原会话。协作期间关闭视图不关闭它持有的原生会话；普通权限/模型切换要求先暂停。

S0–S2 的工具集合仅只读与任务消息。原生权限扩大、写入和未授权工具仍拒绝；不新增权限代批或运行中实时插话。消息在主进程持久化，审批仍归原 Provider；此路径没有可代批的写入审批。

## 验收与发现的问题

1. 真实 CLI 请求用户确认 `allowed=[0,42]` 是否允许 0；在提问时暂停，确认两个活动原生回合停止，用户回复后继续，独立审查和汇总完成。
2. 再关闭原 Claude/Codex Provider，创建新 Provider 与 Service，从相同记录恢复。读取记录未调用模型；明确续跑后保留原生 worker 和发起者身份，并完成 approved 报告。
3. 桌面开发版在原有 Hcode 项目会话中点击“重新审查最新报告”，保留旧审查，新增独立 Claude 审查和原会话汇总；没有创建新报告冒充修订。真实 UI 显示两份审查，版本仍为原 v1，累计回合由 5 变 7。
4. 行为回归运行真实业务服务、工具、证据校验、文件仓库，只替换外部模型传输。覆盖双方澄清、用户代批拒绝、暂停成功/失败、任务级取消、两活动工作者加一个排队者的整体取消、迟到结果、重启不自动派发、证据变化、重审和累计预算耗尽。
5. 真实暂停暴露子任务误标 cancelled、无法恢复的问题，已改为 interrupted 并补回归；另补父会话仍在汇总时保持 running 的回归，防止提前显示结束和无法停止。恢复测试的双重清理错误也已修复，保存了实际完成的记录。

## 范围、限制与下一切片

实现按模块归属：`TaskMessages` 拥有有向澄清与回复；`RunControls` 拥有用户生命周期动作；`RunExecutor` 拥有并发/预算/执行记录；`Repository` 拥有持久化与显式日志修复；Renderer 只展示快照、提交动作。

人工增加预算、改变审查后端/验收标准、直接编辑报告、跨任务任意寻址、跨进程自动续跑均未开放。产品决定需要用户回复；这不是让其他 AI 或宿主代做决定。真实 Provider 退出和重新接入已验证；电源中断/SIGKILL 期间的文件系统故障仅有事件日志回归覆盖，未人为造成整机掉电。其他操作系统、CLI 版本、登录失效/真实额度耗尽仍未做实机验收。

下一切片仍按方案进入 S5a：独立目录中的实现、实际验证、冻结代码版本审查与修订、展示待采纳候选变更。S2 的报告 approved 不代表代码正确、测试通过或代码已应用。

所有代码仍在开发分支工作区，未提交、推送、打包发布或替换已安装 HCode；历史 A10 备份和用户全局 CLI 配置未修改。
