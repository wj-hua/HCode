# HCode 评审后的普通续聊交接与验证能力

日期：2026-10-14。分支：`codex/expert-list-report-preview`。本轮改动与验收记录一并提交，未推送或合入 main。

## 已实现：普通续聊交接

普通消息发送前，主进程查询当前项目、后端及原生会话对应的历史宿主回合。已结束的规划、研究、互审、汇总和验收约束只属于对应回合；普通续聊按最新请求、当前权限及项目规范继续。历史报告和结论保留为参考，静态推断不冒充运行证据。

交接不改写用户原话、不替换原生线程、不删除历史、不授予额外权限，也不自动派发专家或开始修复。新一轮研究不会接收普通交接；活动协作及原生停止未确认仍由原执行锁保护。根据已保存记录及原生身份恢复，新视图 key 或重启不会丢失交接。旧记录缺少逐回合原生 id 时，可用可信主持身份关联。

只向开发者上下文提供宿主校验过的记录身份和状态，不把报告正文或旧目标提升成开发者指令。记录或配置读取失败明确传播，不忽略异常后冒充恢复成功。

### 原生协议验证

首次普通命令执行测试通过后，增加仅用于临时夹具的系统交接标记，发现仅通过 `thread/resume` 更新开发者指令不足以证明新交接已进入模型上下文；原生逐回合模式参数也未通过该验证。

最终 Codex 使用 0.162 的 `thread/inject_items`，追加模型可见的 developer 历史项，然后发送用户原话。无需换线程或伪造用户气泡。研究回合明确声明当前宿主任务范围，普通回合明确解除旧阶段限制。

Claude SDK 默认冻结首次系统提示，后续启动传入新 append 仍可能沿用旧快照。研究及交接使用 `systemPrompt.snapshot=false`，保留 `claude_code` preset，普通交接作为 append；仅在空闲边界关闭旧 query 并按同一原生身份恢复。

参数接受不是验证完成。最终真实 Codex、Claude 均收到临时交接标记，实际运行 `node check.mjs` 并产生验证文件，源码保持不变；Codex 销毁并重建 app-server 进程后，同一线程仍可收到交接、执行脚本并区分旧静态报告与新运行证据。临时标记不进入业务会话。

界面将完成后的限制标明为“本次评审：源码只读核对，未联网、未运行测试”，并提示原会话可按最新请求继续，报告保留为参考。

## 对当前 iOS 场景的判断

纯源码只读评审不足以验证 Xcode 27／iOS 27 适配。应允许编译、检查脚本及测试，但保护目标应是原项目源码和原工作区，而不是禁止一切产生文件的操作。编译会生成 DerivedData、缓存及日志，脚本也可能修改工程或依赖；因此验证应在独立副本执行，产物放入独立输出目录。

本机已核对为 Xcode 27.0（27A266a）。项目存在：

- `XcodeBuild/check-scene-window-access.py`：源码静态窗口接口检查。
- `XcodeBuild/build-scene-navigation-regression.sh`：独立 UIKit 回归 App 构建。
- `XcodeBuild/build-ios27-presentation-regression.sh`：另一套 UIKit 展示回归构建。
- `XcodeBuild/xcodebuild.sh`：包含归档／导出／上传，默认选择上传，不能当成一般评审检查直接执行。

两套独立回归程序抽取部分源码并替换部分媒体和资产依赖。它们成功构建只证明其覆盖范围，不等于完整 App、模拟器或真机行为已经通过。

当前 HCode 隔离交付已有完整复制、原项目沙箱隔离、无凭证环境、进程停止确认及日志绑定能力；检查发现器目前仅支持普通 Node 项目。Xcode 工具链、模拟器服务、构建输出、源文件冻结及脚本白名单需要独立准入验证，不能直接将 Node 检查当成 iOS 支持。本轮完成交接及普通脚本能力恢复，尚未把 Xcode 检查接入专家模式。

## 隔离验证的后续切片

### V0：验证 iOS 工具链及隔离边界

Type：AFK。

What to build：在可丢弃副本验证 SDK／编译器所需的读取、缓存、进程及服务权限；确认原项目读写被阻止、生成文件留在副本或输出目录、停止后无残留运行进程。不运行归档、上传或源码补丁脚本。

Acceptance criteria：实际编译命令和日志可核对；原项目内容及 Git 状态不变；缺 SDK、外部链接、超限或停止未确认明确阻止继续。

Boundaries：宿主隔离工作区与验证运行器；不开放任意原目录 shell，不做代码采纳，不自动扩展网络或签名权限。

Blocked by：无。

### V1：确认源码审查与构建／脚本检查

Type：AFK。

What to build：专家计划可选择“源码审查”或“源码＋隔离验证”，列明实际命令、脚本及构建阶段、复制范围和输出目录。用户确认后执行，命令或项目内容变化使旧确认失效。

Acceptance criteria：只执行已确认检查，退出码、完整日志、超时和取消状态真实记录；校验原源码不变；缺依赖或环境阻塞不会被呈现为通过。

Boundaries：专家草案、检查准入、宿主运行器和结果展示；不替换业务代码，不自动安装依赖或上传 App。

Blocked by：V0。

### V2：把运行证据纳入独立研究与互审

Type：AFK。

What to build：冻结源码版本、命令、环境、日志与产物范围；专家明确区分源码判断、编译证据、脚本测试及设备观察。相关源码变化使旧运行证据失效，原会话汇总真实未验证项。

Acceptance criteria：没有实际运行不能标记测试通过；独立回归不能代替完整 App 验收；旧报告保留，新结果有明确来源和版本。

Boundaries：专家证据契约、互审及汇总；仍不自动修改原源码或把隔离变化采纳回原项目。

Blocked by：V1。
