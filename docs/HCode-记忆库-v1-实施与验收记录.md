# HCode 记忆库 v1 实施与验收记录

已按 [v1 方案](./HCode-记忆库-v1-方案.md) 完成 M1–M3，入口为「设置 → 通知与系统 → 记忆」，默认关闭。

## 实现

- `MemoryRepository` 将每条记忆独立保存到本机 `userData/memories/<uuid>.json`，临时文件加原子重命名；目录权限 `0700`、文件权限 `0600`。保存与删除按 ID 串行处理，服务层串行核对总量，避免并发突破 500 条上限。
- `MemoryService` 提供全局／项目作用域、项目路径 realpath 归一化、关键词检索、敏感信息拒绝和变更事件。非项目对话只读写全局；AI 不能通过替换或删除 ID 修改其他项目的记忆，设置页可统一管理。
- 普通 Claude/Codex 会话可独立组合记忆与委派工具。关闭记忆后停止后续快照和宿主工具读写；Codex 已注册的动态工具名称及此前进入线程历史的内容无法从历史移除。
- Claude 使用系统提示 append 与 `snapshot: false`；Codex 使用独立 developer 消息，按原生线程的快照 hash 去重，记忆变化不触发重新 resume。空库快照也会同步，避免删除最后一条后继续沿用旧快照。
- 快照按全局、当前项目排序，正文与提示总计不超过 3000 字符；未注入条目保留搜索提示。内容标明仅供背景参考，当前用户要求优先。
- 设置页支持新增、编辑、作用域切换、确认删除、来源与更新时间、项目移除标注，以及 AI 写入后的实时刷新。补充中英文文案、输入框状态和 README。
- agy 普通会话、协作研究及委派子会话不接入记忆；不修改 CLI 全局配置，不额外发起模型请求。
