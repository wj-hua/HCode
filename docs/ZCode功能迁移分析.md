# ZCode 功能迁移分析

## 目的与范围

对照本地检出的 ZCode 和 HCode，挑选能改善 HCode 工作流的功能，供后续规划和实施参考。本文是静态源码分析，不代表已经完成运行验证，也不是实施承诺。分析以当前仓库为准：ZCode 是包含自有 Agent、服务和多平台客户端的工作台；HCode 是 macOS 桌面应用，通过各自的适配器接入 Claude Code、Codex 和 Antigravity。

迁移时优先复用现有 HCode 界面、IPC 和适配器，按需借鉴 ZCode 的组件与交互。ZCode 的服务、状态和运行时不能假设可以直接接入 HCode；复制代码时保留许可和第三方声明。

## 建议优先级

| 顺序 | 功能 | 价值 | 粗略规模 |
| --- | --- | --- | --- |
| 1 | 项目文件树 | 浏览项目文件，并与现有预览和改动面板联动 | 中 |
| 2 | 代码行批注 | 针对具体代码或差异整理反馈，交给当前 AI | 中 |
| 3 | PDF 与 Office 文件预览 | 减少办公场景中切换外部应用 | 中到大，取决于格式 |
| 4 | 内置终端 | 在工作台内手动运行命令 | 中到大 |
| 5 | Git 审查增强 | 更清楚地区分和浏览仓库改动 | 按范围而定 |
| 按需 | 手机远程控制 | 离开电脑时查看和处理运行中的会话 | 大 |
| 按需 | SSH 远程项目 | 在远程机器上使用工作区和 CLI | 大 |
| 按需 | 插件体系 | 扩展工作台自身的功能和界面 | 大 |

规模只是根据代码结构作出的相对判断，实际工作量需要在确定范围和验证依赖后评估。

## 功能分析

### 1. 项目文件树

ZCode 有[文件树与文件管理面板](../../ZCode/packages/ui/src/WorkspaceFileTree.tsx)。HCode 已经能从消息、文件引用和改动列表打开文件，也有[文件预览面板](../src/renderer/app/conversation/FilePreviewPanel.tsx)，但缺少独立浏览项目目录的入口。

建议首版支持展开目录、搜索文件、点击预览和复制路径，并复用现有预览面板；后续再考虑新建、重命名和删除文件。需要明确隐藏文件、忽略规则、大目录加载、符号链接及项目切换后的状态。验收时应确认切换项目不会显示其他项目的文件，打开文件与现有预览行为一致。

### 2. 代码行批注

ZCode 包含[代码审查相关逻辑](../../ZCode/packages/ui/src/previewPaneCodeReview.ts)。HCode 已有差异预览和[改动摘要](../src/renderer/app/conversation/TurnChangeSummary.tsx)，可在此基础上增加对具体行或行范围的反馈。

建议首版支持选择代码或 diff 行、输入意见，并将文件路径、行号和意见加入当前输入框，由用户检查后发送。需要区分当前文件与历史 diff 的行号，文件变化时避免将旧批注误认为仍然准确；先支持普通会话，再考虑与协作候选交付联动。

### 3. PDF 与 Office 预览

ZCode 的 UI 包含 PDF、DOCX、XLSX 和 PPTX 等预览组件。HCode 目前已支持代码、Markdown、HTML、图片等预览，其他类型可交给系统应用打开，详见 [HCode 文件预览](../src/renderer/app/conversation/FilePreviewPanel.tsx)。

建议先支持 PDF，再根据实际使用频率决定是否接入 Word、表格和幻灯片。每种格式分别核对现有组件依赖、打包体积、文件大小限制、隔离方式与失败提示；不支持或无法解析时继续提供系统应用打开入口。

### 4. 内置终端（首版已实现）

ZCode 有[终端面板](../../ZCode/packages/ui/src/SidePaneTerminalPane.tsx)及终端会话保活设计；HCode 的会话菜单已有[在外部终端打开](../src/renderer/app/shell/SessionItem.tsx)入口。

建议先做本地单终端，工作目录跟随所选项目，并定义切换会话、收起面板、关闭项目和退出应用时的进程生命周期。终端是交互式进程，需要单独处理输入、尺寸变化、退出与清理，不能只复制界面。多标签和跨项目保活可在首版稳定后评估。

当前本地底部终端支持每个项目多个标签，切换会话、项目或收起面板时继续运行；关闭非最后一个标签、关闭项目最后一个会话视图、窗口或应用时回收对应终端。最后一个标签的关闭按钮只收起面板，shell 自行退出时则删除标签。终端使用本机登录 shell，不自动接管已有 CLI 会话；详见 [HCode 内置终端设计](HCode内置终端设计.md)。

侧边终端采用与底部终端独立的标签和进程；关闭侧边标签会结束该终端，收起面板或切换到文件预览时保留运行状态。入口与文件预览的组织方式沿用 HCode 的侧栏布局；HCode 尚不支持 ZCode 的远程工作区终端与内嵌浏览器。

### 5. Git 审查增强

HCode 的 [Git 工具](../src/renderer/app/conversation/GitTools.tsx)已经支持查看工作区改动、分支操作、提交和推送；ZCode 的 [Git 面板](../../ZCode/packages/ui/src/GitPane.tsx)提供更丰富的改动浏览体验。

建议优先评估暂存与未暂存改动的清晰区分、文件搜索、从改动跳转文件树。提交历史图等功能按需后置。涉及暂存、撤销或其他写入操作时，需明确操作范围、用户已有改动和失败反馈。

### 6. 手机远程控制

ZCode 有[手机远控架构](../../ZCode/docs/web-remote-control/web-remote-control-architecture.md)，包括连接桌面会话与状态恢复。HCode 当前是本地桌面工作台，三个 CLI 的运行和审批状态由 HCode 管理。

如果确实需要离开电脑后查看进度、发送消息或处理审批，可单独立项：先定义连接与认证、会话状态所有者、断线重连、消息队列和审批语义，再评估三个 CLI 的能力差异。不能仅复制手机界面或假设 ZCode 的服务端协议适用。

### 7. SSH 远程项目

ZCode 支持 SSH 等远程工作区；HCode 的[多 CLI 接入](../README.md)目前依赖本机进程、会话记录和文件路径。

需要时应先验证远程 CLI 的安装与认证、会话发现、路径身份、文件操作、Git、附件和断线恢复，明确每个 CLI 的支持范围。此项涉及适配器和工作区架构，适合单独设计。

### 8. 插件体系

ZCode 有[插件与 UI 插件机制](../../ZCode/UI_PLUGIN.md)。HCode 已提供 Claude、Codex 的 [MCP 与技能管理](../src/renderer/app/settings/ExtensionsSection.tsx)，无需为已有管理能力重复建设。

只有需要第三方扩展 HCode 界面或能力时，才考虑完整插件宿主。届时需要定义插件权限、生命周期、版本兼容和隔离，并逐项确认与不同 CLI 的关系；ZCode 插件不能默认直接兼容 HCode。

## 已有能力与 HCode 自身规划

HCode 已具备会话全文搜索、排队发送、`@` 文件引用、斜杠命令、部分 CLI 的会话分叉、Git 基础操作、MCP/Skills 管理、任务通知和多模型对比等能力，不应作为缺失功能重复迁移。具体支持范围以 [HCode README](../README.md) 和当前源码为准。

HCode 的[功能规划](HCode-功能规划.md)还提出给普通多模型对比使用独立 Git worktree，以减少多个模型同时修改同一目录的冲突。这与 ZCode 迁移不完全相同，但值得结合 HCode 的多 CLI 工作流单独评估；现有协作模式中的隔离代码交付和冲突检查不能直接等同于普通对比的 worktree 隔离。功能规划中的部分历史描述可能过时，实施前应重新核对源码。

## 推荐实施顺序

先做文件树，再做行批注，然后按需求接入 PDF 预览、终端和 Git 审查增强。手机远控、SSH 工作区和插件宿主均应按实际需求单独设计，不作为前几项的前置条件。每项启动前确认具体交互、状态归属、支持范围和验收场景。
