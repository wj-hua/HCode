## 完成行为与边界

问题卡明确标注提问者与回复目标，任务使用实际目标首行，专家使用角色与 AI。用户点击“仅保存回复”或“仅保存资料”后收到保存反馈；资料只绑定指定交付 / 专家，没有跨会话广播，也不启动模型。原会话仍活动时保存用户回复同样不自动续跑；发起 AI 回答已有上下文的原有受限能力保留，不能代替用户决定。

续跑分为选择和明确开始两步。选择阶段只展示目标、执行 / 研究、验证、审查与原会话汇总路径，以及累计回合、最少预算和阻止原因。只有“开始此续跑”派发模型。单任务只重做指定交付；专家单项续研保留其他专家报告，再按原团队重新互审和汇总。全部重新研究与部分参与各自展示影响范围，不以排除失败专家作为默认策略。

新资料不能沿用上一轮汇总充当已核对结果。保存到已完成任务后旧汇总失效，冻结报告、审查、原生历史及事件记录保留；未重新执行或审查前保持待处理。源文件、报告、候选、配置 hash、原生会话占用、采纳租约和累计预算仍由主进程原有模块复核，界面预算提示不替代宿主准入。

“请求暂停”只发出停止请求；收到原生确认并恢复源会话后，才出现“接管原会话”。接管动作再次核对暂停状态、全部回合是否空闲及候选停止状态，然后打开真实源会话、切回普通对话、关闭任务面板并聚焦输入框；不发送消息、不更改权限。原生停止失败或超时且未确认时保持 stopping 和原生锁，不能接管、续跑或误发普通聊天。同一进程收到可信迟到终态后，可点击“核对停止状态”复核锁并恢复源会话；历史错误保留，不自动续跑。未完成采纳或候选停止未确认仍禁止接管。重启后的活动记录显示 interrupted / 状态未知，不把新宿主没有活动进程的展示当作原执行已安全停止。

重启只读取记录，不派发模型。保存的资料、答案、冻结版本、审查与原生身份沿用。专家续跑、补资料、回复与候选生命周期使用同一个 Run 操作互斥入口，避免用户操作相互覆盖。

澄清后的执行由宿主标注阶段：已回答的首轮问题不重复等待；若工作者幂等查询旧问题，工具返回真实回答与 answered 状态；确有不同的新问题仍可重新请求澄清。只读和代码执行共用这一阶段规则，原会话的任务结果工具可以读取该任务的完整消息，而不把“没有待答问题”误当作“用户没有回复”。资料始终是数据，不扩大既定写入范围、命令能力或权限。

业务域限于协作人工操作和恢复呈现。入口是问题卡、任务 / 专家恢复动作及对应 IPC；主进程负责状态、证据准入与 IO，界面负责未保存输入和操作反馈。新增 `collaboration:supplement`、`collaboration:takeover`，沿用原 `reply` / `resume` / `resumeExperts` / `pause` / `cancel`。TaskMessage 原 `deliveryId` 在 context 类型也可指向专家 id，旧结构无需迁移；补充和查询只能访问所属 Run 的目标。

## Apple Design 落地

控制靠近影响目标，保存、选择、开始、等待确认与接管使用不同标签及反馈。续跑预览自动定位并获得可见焦点；返回选择不会执行。使用现有字体、色彩、Button、可见焦点和按压反馈，没有新增动效框架或强制转场。任务面板关闭与重新打开保留原导航；接管后的输入方式明确回到普通对话。
