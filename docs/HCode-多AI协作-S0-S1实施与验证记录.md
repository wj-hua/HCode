# HCode 多 AI 协作：S0 / S1 实施与验证记录

日期：2026-10-11。对应《HCode-多AI协作技术方案与实施计划》中的只读研究路径。当前开发分支：`codex/multi-ai-collaboration-plan`。

后续真实修订验收与 S2 状态见 [S2 实施与验收记录](./HCode-多AI协作-S2实施与验收记录.md)。下文保留首次 S0/S1 交付范围。

## 已落地的行为

当前 Claude 会话调用宿主委派工具，把只读调研交给用户选择的 Codex 或 Claude。宿主冻结报告版本，创建独立 Claude 审查会话；出现具体阻塞意见时，在原执行会话修订报告，生成新版本并重新审查。最多两次自动修订、三次审查；无法判定、格式/证据错误、执行失败、预算不足均保留明确原因。完成后回到原发起会话汇总；失败结果也会回报，但不接受失败交付。

会话输入框上方新增“多 AI 协作”。界面显示执行者能力、阶段、交付版本、审查问题和原生任务记录。发起者使用当前会话的 sessionKey / 原生身份，协作期间暂时锁定普通消息入口；可信终态后移除研究工具、恢复原权限。没有切换用户选择的 AI 品牌。

每个 Run 由主进程持有，最多两个执行/审查回合并发、12 个原生回合，给强制审查和汇总预留预算。重复 requestKey 返回同一交付；等待工具最多等 30 秒，后续由宿主等待任务并触发一次汇总，界面关闭不停止调度。

真实 CLI 验证使用临时文件夹，读取可见信号，拒绝越界及写入；另直接运行同版本 Codex 沙箱命令，确认操作系统拒绝写入和范围外读取。真实 Codex 回合取消后，共享 app-server 仍可处理请求。原生错误、缺失终态、重复/迟到事件、进程退出通过外部传输边界的回归测试验证，未故意制造账号额度耗尽。

首次真实复测暴露了适配问题：发起者可能要求“不运行任何命令”，而 Codex 最初只有 shell 读取路径，导致空报告。系统把它明确标为待人工处理。随后接入 Codex 原生动态读取工具，并实测工具调用及原生只读沙箱；现在禁止 shell 时仍可读取源码。没有删改失败记录来冒充成功。

## S1 交付门槛与记录

报告必须包含结论和实际文件的逐字源码引用。原生 Codex 的 final_answer 与进度说明分别处理；最终结果不混入 commentary。宿主核对路径、完整行、文件内容 hash；产物单独以 UUID 保存，并记录内容 hash。每次审查引用冻结 versionId，旧版本通过不能接受新内容。审查接受及汇总前后再次核对报告、源码证据；变化后需要人工处理。

审查结果分为通过、需要修订、无法判定。审查者的后端、独立会话 key 和原生身份由宿主从真实结果记录，模型不能伪造；历史记录缺失身份时明确显示未知。需要修订必须包含阻塞问题及 issue id、定位、原因、证据和建议。模型回合成功、报告被接受和代码验证成功是不同状态；当前只读路径没有验证执行器，不显示“测试通过”或“代码已应用”。

Run 事件带连续序号，先写事件日志再原子替换快照，报告按版本单独存储。渲染事件携带完整快照并拒绝旧序号覆盖；历史会话可通过原生会话身份找回记录。重启时进行中的状态显示 interrupted，禁止自动重跑；事件尾行不完整或损坏会明确报错，恢复修复属于 S2。

开发版记录目录为 Electron userData 下的 `collaborations/<runId>/`，包含 `events.jsonl`、`run.json` 和 `artifacts/`。开发版与已安装正式版的数据目录沿用项目原有隔离。
