# HCode 多 AI 协作 S3 实施与验收记录

日期：2026-10-11。范围：专家独立研究、环形互审及当前原会话汇总。使用已有 Claude SDK、Codex app-server 与 Antigravity CLI Provider；真实验证沿用本机登录状态，未修改 A10 历史备份。

## 1. 可用入口与交付边界

开发版 HCode：打开空闲的 Claude/Codex 当前会话 →「多 AI 协作」→ 任务类型「专家独立研究与互审」→ 输入目标并选择 2–3 位专家、后端与模型 → 启动。发起者由当前会话确定，汇总保持其原生身份。已有 Codex 线程仍需满足 S1b 的工具目录兼容条件，不能换线程绕过检查。

当前通用角色为架构、实现、验证，每位角色可配置 Claude、Codex 或 agy/Gemini。Gemini 必须从实际账户模型列表选择；Claude/Codex 留空时显示“CLI 默认（未核对具体模型）”。相同后端和模型会提示来源重复，不把多个角色冒充独立模型。

首版只读源码：不开放命令、测试、联网或写入。两位互相审查，三位采用一轮环形审查，每份有效报告有一位不同参与者审查；未实现全互审或自动辩论。七类复合专家（iOS、安卓、前端、Java 服务端、需求调研、UI 设计、测试）及本机角色/Skills 冻结加载归 S3b，不能把本次三通用角色视为七类能力验收。

## 2. 调度与状态归属

主进程持有参与者、报告版本、阶段、审查关系、累计预算、失败与汇总。Renderer 只维护配置草稿、展示快照和展开状态。

1. 当前原会话确认目标和只读范围，不能自由派发新专家。
2. 每位专家在各自会话独立调研，只收到共同目标、自身职责和只读工具，不收到其他专家报告。
3. 首轮所有任务终结后，宿主验证并冻结有效报告。任何专家失败时停止推进，用户可显式重试，或至少有两份有效报告时选择部分继续；失败参与者与原文保留。
4. 对冻结的最新报告安排环形互审。审查使用独立新会话，收到自身报告、指定目标版本与 claim，逐条给出支持、分歧或证据不足。
5. 所有指定审查完成后，当前原会话生成结构化汇总，经宿主再次核对引用、审查覆盖和源码一致性才发布成功。

基线为 1 次主持确认 + N 次独立调研 + N 次互审 + 1 次主持汇总：两人 6 回合，三人 8 回合。累计上限 12 回合，执行/审查并发最多 2；每项格式修正最多一次，并为剩余必要阶段预留预算。显式重试和恢复不会重置累计用量；额度或模型失败不自动换后端。S3b 增加参与上限前必须单独调整专家预算。

暂停阻止新派发并确认原生终态，停止后不能继续取消的 Run。重启把未知活动状态标为中断，不自动重跑；用户选择重研、复审或部分继续时重新核对能力、模型、原会话身份、报告文件及源码，生成新尝试并保留旧版本。

## 3. 报告、证据与汇总校验

独立报告使用现有报告契约；每条 finding 有唯一稳定 claimId 和准确源码行引用。宿主读取真实文件，校验路径、行号、quote，并补充内容 hash。原生回合成功不等于报告有效；不合格原文保留并显示错误，超过保存上限显示截断，不生成空报告冒充通过。

报告目录须在专家可读项目外。准入同时核对 macOS 路径别名和符号链接，阻止通过目录布局读取同组历史报告。该限制与 Provider 的受限工具协同生效，不宣称构成 OS 级全项目沙箱。

PeerReview 绑定 targetId、versionId、versionHash、reviewerId 与每个 claimId。目标 claim 必须各出现一次；支持或反驳须附真实源码证据，宿主补充 hash；证据不足可以没有源码引用。旧版审查保留，不能证明新版通过。

汇总分为共识、分歧、待验证和局限。每项引用必须指向真实参与者、报告版本和 claim；共识至少涉及两位专家，且对应 claim 的指定互审均支持。所有被反驳的 claim 必须出现在分歧中，所有证据不足的 claim 必须出现在待验证中；失败专家清单不得遗漏。模型自然语言结论仍需人核对，宿主引用校验不能证明所有措辞或推理都正确。

阶段上下文 hash 覆盖当前有效报告实际引用的文件，并在互审/汇总前后复核；互审新增证据也复核。源文件在汇总中变化时拒绝发布旧汇总。此机制不是整个项目的原子快照；未引用文件、文件变化后又恢复原字节等情况不由本切片保证。

UI 展示参与者、模型、报告版本、逐 claim 互审意见、源码 quote/hash、失败原文、主持三类汇总和原生回合记录。汇总引用可打开对应冻结报告；错误、部分继续和累计预算均可见。

## 7. 模块边界与后续

- `shared/experts.ts`：角色、参与者、互审和汇总契约；`shared/collaboration.ts` / IPC 保持委派兼容。
- `main/collaboration/experts/`：准入、预算、契约、证据、单回合有界校正、阶段编排和显式恢复分责。
- `CollaborationRunner`：两类流程共用的结束、停止与原会话释放；原生执行仍经 `RunExecutor` / `SessionExecutionService`。
- Renderer：专家配置、参与者报告、逐项审查、汇总与恢复控件分别管理展示职责。

未验收：网页/联网研究、七类角色与 Skills 的实际效果、自动回应轮次、agy 当前会话发起、多于三位专家、Gemini 写入、原项目采纳，以及其他平台/CLI 版本。实际配额耗尽未消耗账号来验证；错误与预算边界由既有协议和 Service 测试覆盖。
