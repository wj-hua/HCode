# HCode

macOS 桌面版编程助手工作台，界面与对话卡片复刻 [ZCode](../ZCode)。支持 **Claude Code**、**Codex**、与 **Antigravity** 三个 CLI（同一套界面，会话按项目混排）：

- 项目列表：手动添加、置顶或移除项目文件夹；根据各 CLI 的会话统计已添加项目的会话数和最近活动时间
- 不在项目中工作：从首页、输入框项目菜单或侧边栏“对话”旁的 + 开始非项目会话；草稿切换保留文字与附件，历史归入独立的“对话”分区，支持三种 CLI
- 会话置顶：右键置顶常用会话，在所属项目内优先显示，重启后保留；删除或归档时自动清理置顶记录
- 会话历史：按已添加的项目列出各 CLI 的历史会话（包括终端里创建的），用 ZCode 卡片查看完整对话
- 新建会话 / 续聊历史会话，流式输出，随时停止（Esc）
- Git 改动面板：查看本轮差异、勾选文件提交、生成提交说明、确认撤销到发送前；新会话可创建并切换分支
- 改动历史：每个会话保留最近 20 轮文件清单和增删行，重启后可选择轮次查看；历史预览会提示文件后续变化
- 文件预览：点击消息中的文件链接、自动识别的普通文件路径（如 `docs/方案.md`、`design/prototype.html`，也支持行内代码路径）、`@` 文件引用、附件或工具卡片里的文件，在右侧分栏查看内容，分界可拖拽调宽，保持会话及输入框可见；Markdown 可切换预览与源码，HTML 默认显示可交互页面并可切换源码。HTML 页面通过隔离协议直接加载，支持至 2 MiB，不受源码高亮的 256 KiB 阈值影响；超出高亮阈值仍可切回页面。相对路径按当前会话项目解析，网址和代码块示例不自动转换；支持刷新、在 Finder 显示和用默认应用打开，二进制及超过 256 KiB 的普通文本文件提示使用系统应用
- 输出速度：输入框旁显示最近一轮 TTFT（收到首个非空模型流式输出后出现）和估算 tokens/s（本轮结束后出现）；支持三种 CLI，分段计时排除工具执行与审批等待。Claude 按主代理每次 `message_start` 到最终 `message_delta` 的完整响应时间，与该区间的累计输出 Token 增量配对，涵盖隐藏思考，并核对各次响应最终用量之和与本轮用量一致；Codex 显示平均响应吞吐，以整轮输出 Token 除以完整轮次耗时扣除可识别工具/审批等待后的时间，包含首输出前的请求等待和隐藏思考，并显示有效响应耗时；重叠工具/审批只扣一次，模型同时输出的时间不扣除，缺少工具起止事件或中断时不显示吞吐。Antigravity 按流式片段估算。TTFT 包含 CLI 启动；速度受流式缓冲影响，缺少对应的用量或计时数据时不显示，不为旧历史补算
- 应用背景：在设置中选择图片或视频（静音循环）作为全窗口背景，并可调节模糊程度和蒙层浓度
- 任务清单：输入框上方固定显示完成进度和当前任务，可展开完整清单；支持 Claude Code 和 Codex，对比分栏分别显示
- 附件输入：可粘贴、拖入或选择图片、视频、文档、APK 等文件；Claude Code、Codex 的图片按原生图片输入发送；Antigravity 的图片和其他文件以本地路径提供给 CLI 读取，发送后显示文件卡片（图片显示缩略图）
- 审批卡片：Claude Code、Codex 的工具审批与提问；Antigravity 无头模式不能交互审批，需要确认的操作会自动拒绝
- 按 CLI 提供各自支持的权限模式与模型切换
- 多 AI 协作：当前 Claude/Codex 会话委派其他 AI，自动独立审查、有界修订并回到原会话汇总；支持七类角色/Skills 专家只读互审、单候选或两项独立副本代码交付，以及用户确认的冲突检查、安全采纳和恢复
- 界面模式：在设置中切换编程模式与办公模式；办公模式收起命令和代码改动细节，编程模式保留完整工具信息
- 已添加项目中，终端新建或更新的会话会自动刷新；Claude Code 正在终端运行的会话会提示冲突风险
- 订阅额度：侧边栏底部显示 Claude Code、Codex、Antigravity 的 5 小时和每周剩余额度，点开查看分组明细与重置时间（API key 等没有订阅额度的登录方式会注明）

## 使用

需要 Node 24+、pnpm 10+，以及已登录的 `claude`、`codex`、`agy` 中至少一个命令（默认从登录 shell 的 PATH 查找，可在设置里指定路径）。

```bash
pnpm install
pnpm dev          # 开发模式（Vite HMR + 主进程自动重启）
pnpm typecheck    # 类型检查
pnpm test         # 单元测试（vitest：各 CLI 投影器、附件清单）
pnpm dist         # 打包 release/HCode-<版本>-arm64.dmg（本地未签名）
```

开发调试：`HCODE_CDP_PORT=9229 pnpm dev` 开启远程调试端口；`HCODE_DEBUG=1` 打印 claude 子进程 stderr。

常用快捷键：⌘K 快速切换项目或会话，⌘F 搜索会话全文，⌘1–9 切换已打开的会话，⌘W 关闭当前会话视图，⌘L 聚焦输入框，⌘⇧C 复制最后一条回复；⌘N 新建会话，⌘B 切换侧边栏，⌘, 打开设置。

## 协作、专家评审与对比

普通 Claude/Codex 对话提供统一的 `call_agent` 工具，可委派 Claude、Codex 或 agy/Gemini。你可以直接说「你让 Codex 调整吧」「让 Claude 审核一下」或「让 Gemini 完成这个任务」；原话完整交给当前 AI，由它结合会话决定是否调用、执行者、提示词、模型和只读 / 执行模式。宿主不解析句式，不预先生成计划，不自动安排额外互审。调用开始后右侧自动展示实际参数、原生工具进度和审批；完成或失败作为工具结果返回同一源回合，当前 AI 可继续下一步，也可续接同一子会话。关闭右侧不取消调用，停止源回合会同时请求停止子会话；未获原生停止确认时继续阻止同项目的新写入。

需要 Gemini 实现 UI、Codex 实现业务等并行分工时，主 AI 使用 `call_agents` 一次提交最多两项独立实现任务，每项含 `taskKey`、`agent`、完整 `prompt`、准确的项目相对文件清单 `allowedPaths` 及可选 `model`。目录、通配符、越界路径、链接或大小写歧义不能作为文件范围；任务清单重叠时整批不启动，工具返回冲突文件、任务键及调整提示词和分工的建议。共享接口和配置交给唯一任务先完成，依赖任务随后派发，不能只在提示词里声明互不冲突。

并行子任务使用受限运行时关闭原生写入与命令，仅经宿主 `write_file/delete_file` 修改授权文件；宿主检查当前活动作用域、路径及读取所得 hash。越界和版本变化的反馈既交给子 AI，也直接保存在调用记录并返回主 AI；即使原生回合返回成功，有写入反馈的整批仍标记为需核对的未完整交付。普通 `call_agent` 的项目写入互斥保留，受限任务不能借普通续聊扩大权限。并行时主 AI 不直接写项目，结束后由它核对每项实际结果、未完成项并执行原授权内的集成检查；子任务没有运行构建或测试，不能把模型自述当成验证通过。Gemini 受限写入使用已验证的 macOS agy 1.3.3/1.4.3，Codex 使用已验证的 0.162.x/0.163.x 受限协议；未准入时明确拒绝，不降级为普通执行。

从侧边栏独立打开本次应用运行期间的子会话时，页面会关联同一原生会话的实时内容、运行／审批／结束状态、实际模型与用量；切走再返回或续接同一子会话时继续同步。打开页面不重跑任务，迟到的历史读取不会覆盖已收到的实时内容。历史工具查询里的状态保留当时的返回值，会话当前状态单独更新。

`list_agent_targets` 返回已注册 CLI 的可用状态、原生模型列表及能力限制；查询不会启动 AI 任务。Gemini 使用 `agent=agy`，模型必须来自 agy 返回的 Gemini 列表，可显式选择或沿用设置中的有效默认模型；不可用或无法确认时明确失败，不自动换模型。当前没有独立 `gemini` 命令或自定义任意命令入口。Cline 保持移除。

agy/Gemini 支持只读与执行委派；只读使用 HCode 隔离研究角色和有界项目读取工具，当前验证 macOS agy 1.3.3、1.4.3。执行使用 agy 的原生工具与权限，仅在源会话已完全放行时继承为完全放行，否则沿用 agy 设置。无头模式不能交互审批，被拒绝的操作明确返回失败。成功调用可续接同一原生会话并沿用原模型；只读与执行角色之间需新建调用。agy 作为主会话自主发起委派尚未接入。

只读调用使用受限研究运行时；普通 `call_agent` 执行调用在当前项目直接工作，继承原会话已选择的权限，其他情况沿用目标 CLI 的审批，不替原会话提权。不自动写入 Git 提交、推送或扩大授权。调用记录重启后可读，旧活动记录不会自动续跑。已有 Claude 会话保留原生身份追加工具；新建普通 Codex 会话创建时注册动态工具，旧 Codex 线程保留已有的匹配工具，缺少批量工具时明确说明限制，不偷换线程；使用新增 `call_agents` 并行委派请新建 Codex 会话。

右侧优先展示所有正在调用或等待停止确认的调用；并行批次中的任务分别展示状态、文件范围和写入反馈，先完成的任务持续保留，不因另一项仍运行而隐藏。全部结束后展示最新调用或最新批次的全部结果。更早的调用收进「历史调用」，展开后可查看完整结果和原生记录；新调用开始时自动收起历史，避免旧结果占据当前进度下方。

输入框的「工作方式」仍提供手动协作入口，切换方式保留当前文字和附件；切换本身不调用 AI。

| 工作方式 | 适用场景 | 开始动作 |
| --- | --- | --- |
| 普通对话 | 与当前 AI 对话 | 发送 |
| 协作执行 | 当前 AI 委派其他 AI，独立审查和有界修订 | 查看并确认计划 |
| 专家评审 | 多角色独立研究、交叉审查、原会话汇总 | 推荐并确认团队 |
| 多模型对比 | 同一输入分别回答并排展示；不自动互审 | 选择其他 AI 后发送并对比 |

协作由当前 Claude/Codex 会话主持。填写目标，可用 `@项目文件` 引用；查看计划、调整任务 / AI / 模型、保存修改，再明确点击开始。生成计划只读项目；确认前不派发执行、创建代码副本或运行检查。输入附件尚未接入协作，有附件时保留草稿并显示原因，不自动忽略附件。关闭侧面板后已启动的协作继续；「协作计划与记录」和侧边栏任务组都返回同一运行。

专家团队依据实际目标和项目资料推荐，可选择 2–7 位 iOS、安卓、前端、Java 服务端、需求调研、UI 设计、测试专家，使用冻结的本机组合角色与 Skills。未知项目需用户选择团队。模型、组合详情及预算按需展开；同品牌和模型的不同角色不代表独立模型来源。专家先各自研究，再由相关角色互审，当前原会话汇总共识、分歧及未验证项。点击结论可核对冻结版本、准确源码和引用范围；原始提示词、JSON 与原生记录在详情中保留。

需要实现时选择「隔离代码交付」。核对单项或双项任务的准确文件范围、执行者、审查者、完整复制清单和宿主检查命令，保存修改、接受范围与检查后开始。写入重叠、依赖关系、路径不合法、缺检查或版本变化会阻止开始。两项共享累计 12 回合预算，各自实现、验证、审查和修订，通过后仍是待采纳候选。逐项查看差异和冲突，再明确确认采纳；原文件变化或未完成恢复会阻止操作。采纳是写回原项目，不是 Git 提交或合并；组合结果仍需在原项目复测。

研究中，主会话逐位展示专家的真实研究／互审状态和已完成数量；暂停或停止后不保留运行指示。完成后，评审结论、共识、分歧、未验证事项与局限默认完整展示在主会话，可复制全部结果或点击引用打开冻结报告。消息与结果共用滚动区；用户向上阅读时不自动拉回底部，首次收到完整结果先显示结论开头。

协作面板直接列出全部专家的身份、状态与最新报告入口；单个专家的任务、报告版本和互审详情按需展开。「查看报告」及主会话结论引用打开独立弹窗，固定头部标明专家、后端和版本，正文独立滚动；引用定位到对应结论标题。关闭按钮、Esc 或点击遮罩退出，焦点返回原入口；Esc 不关闭下层协作面板。列表内不插入报告或空预览区。关闭不会删除报告，迟到的读取响应也不会重新打开弹窗。Codex 评审结束后的普通续聊及重启恢复继续支持该线程已有的项目读取工具；读取仍限于项目目录，旧协作的委派与上下文动作不会继承到普通会话。

规划或评审结束后，普通续聊获得明确的宿主交接：旧阶段及验收限制只属于对应历史回合，报告继续作为参考，按最新请求和当前权限继续。交接不替换线程、不改写用户原话、不自动启动专家，也不扩大权限；本轮用户的新限制仍有效。原生会话关联在重启后继续生效。源码只读评审不等于运行验证；当前专家模式尚未接入 Xcode 构建，普通续聊恢复的命令能力也不代表已有报告通过了测试。

协作面板的左侧分界支持拖拽、左右方向键、Home／End 和双击重置，宽度会保存在本机。宽窗口同时保留消息阅读空间，窄窗口使用可关闭的覆盖面板。会话与协作面板采用统一的 14px 正文、12px 辅助信息；输入框用量和输出速度单独成行，其余控件可随宽度换行。

需要补资料时，问题卡标明发送者与目标。「仅保存回复 / 资料」不启动 AI；新资料使旧汇总失效，旧版本与审查仍保留。选择指定任务 / 专家和阶段，先查看续跑目标及预算，再点击「开始此续跑」。单项续研保留其他专家报告，团队重新互审；预算不重置，不自动换模型或加额度。

「请求暂停」先等待原生确认，确认并恢复源会话后才能「接管原会话」，随后切回普通对话。停止未确认继续等待并保持锁，同一进程收到迟到终态后可以「核对停止状态」。整体停止后该 Run 不能续跑；重启仅恢复记录，不自动调用 AI。未知原执行状态、未完成采纳和候选停止未确认均明确阻止不安全操作。

旧协作记录、计划和原生会话保持可读；没有可信回合关联的历史内容保留原文。已存在的 Codex 普通线程若不能补充宿主工具，会显示原因；从新 Codex 会话进入协作即可。手动协作／专家评审中的 agy/Gemini 仍限只读研究与审查，隔离代码交付与自主主持尚未准入；普通对话的 `call_agent` 执行委派使用上述原生执行路径。

## 键盘与可访问性

工作方式菜单可用键盘选择，Escape 关闭并返回输入；协作面板 Escape 关闭并返回入口，查看文件后可返回原任务。操作反馈分别说明保存、启动、等待、完成和失败。图标按钮提供可访问名称。原生「视图」菜单提供放大、缩小和恢复默认大小；界面响应 macOS「减少动态效果」，关闭循环位移、平滑滚动及视频背景自动播放，同时保留文字、颜色和状态反馈。

未签名的 dmg 首次打开如被拦截：右键 HCode.app →「打开」，或执行 `xattr -dr com.apple.quarantine /Applications/HCode.app`。

## 多 CLI 兼容方式

Electron 主进程为每个 CLI 实现 `AgentProvider`，由 `AgentRegistry` 按 CLI、会话和审批请求路由。各适配器把历史记录和实时事件转换为同一套 ZCode v4 `ConversationRow`；渲染进程通过统一的 IPC 接收行增量、运行状态和审批事件，因此共用项目列表、时间线与输入框。

| CLI | 历史会话 | 实时对话 |
|---|---|---|
| Claude Code | Agent SDK 的 `listSessions` / `getSessionMessages` | Agent SDK `query()`，审批走 `canUseTool` |
| Codex | `codex app-server` 的 `thread/list` / `thread/turns/list` | 所有会话共用一个 app-server，使用 JSON-RPC 的 `thread/start` / `turn/start` 和审批请求 |
| Antigravity | 读取本地 transcript 和 SQLite 元数据 | 每个会话一个 `agy` stream-json 进程；无头模式没有交互审批 |

项目列表只包含手动添加的文件夹。若某个 CLI 的历史会话属于尚未添加的目录，需先添加该项目文件夹，才能从侧边栏查看会话。

非项目对话无需添加文件夹。HCode 在自己的应用数据目录中管理共享工作目录，正式版为 `~/Library/Application Support/HCode/workspace/default`，开发版为 `~/Library/Application Support/HCode-dev/workspace/default`。目录在首次使用时创建，重启后保留生成的文件，各 CLI 的历史仍由原 CLI 保存。它不会进入最近项目列表，也不会改变所选 CLI 的权限模式；需要处理已有项目时，可在未发送的草稿中重新选择项目。

```
src/main/        Electron 主进程
  agents/types.ts  AgentProvider 接口；registry.ts 按 CLI / 会话 / 审批路由
  agents/claude/   Claude 接入：Agent SDK（listSessions / getSessionMessages / query）
  agents/codex/    Codex 接入：codex app-server JSON-RPC（thread/list、thread/turns/list、turn/start、审批请求）
  agents/agy/      Antigravity 接入：读 ~/.gemini/antigravity-cli 的 transcript 历史；每个会话一个 `agy -p` stream-json 进程
  agents/rowProjectorBase.ts  各 CLI 投影器公共部分：把记录 / 流事件投影为 ZCode v4 ConversationRow
  agents/quota.ts  订阅额度解析：Claude SDK usage 请求 / codex account/rateLimits/read / `agy -p /quota` → AgentQuota
  quotaService.ts  额度缓存与刷新（过期重读，对话结束或 CLI 推送额度变化后重读），推送 quota:updated
src/preload/     contextBridge 暴露 window.hcode（通道白名单见 src/shared/ipc.ts）
src/shared/      主/渲染进程共用类型与 IPC 契约
src/renderer/
  app/             HCode 自己的界面：外壳、侧边栏、时间线、输入框、审批卡片、设置
  zcode/           从 ZCode packages/ui/src 复制的组件（卡片、markdown、shadcn 组件、样式）
                   带 “HCode shim” 注释的文件是对 ZCode services/store 依赖的替代实现
vendor/          ZCode 的 @zcode/shared、@zcode/model-option-map 原样复制；@zcode/services 为类型桩
docs/            方案文档
```

以后接入其他 CLI：在 `src/main/agents/` 下实现 `AgentProvider`（历史读取、会话驱动、审批），
投影成同样的 `ConversationRow`；同时扩展 `AgentKind`、默认设置和 `src/shared/agents.ts` 的描述，
在主进程注册适配器，即可复用现有界面。
